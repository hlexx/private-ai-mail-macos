# Trust MVP Gmail Baseline

This audit keeps Gmail as the reference implementation for the provider contracts in ADR 0005. It covers the current P0 user actions and records whether each path reaches a Gmail provider call, local persistence, and a visible failure state.

| Action | Current code path | Expected provider call | Expected local state | Expected user-visible failure | Test coverage |
| --- | --- | --- | --- | --- | --- |
| Archive | `InboxView.onArchive`, `ThreadView.onArchive`, keyboard `E`, and action sheet `.archive` route through `MainScene.archiveSelectedThread` or inline archive closures to `MailMutator.archive`. | `GmailAPI.modifyThread(id:addLabelIds:[], removeLabelIds:["INBOX"])`. | `thread_label` removes `INBOX`; selected reading thread is cleared when archived from the reading pane. | Toast: `Archive failed`; optimistic labels roll back in `MailMutator`. | `MailMutatorTests.archiveRemovesINBOXLabel`; keyboard dispatch tests cover the shortcut boundary. |
| Unarchive | Toast undo action `.unarchive` routes through `MainScene.handleUndo` to `MailMutator.unarchive`. | `GmailAPI.modifyThread(id:addLabelIds:["INBOX"], removeLabelIds:[])`. | `thread_label` restores `INBOX`. | Toast: `Undo failed`; optimistic labels roll back in `MailMutator`. | `MailMutatorTests.unarchiveAddsINBOXLabel`. |
| Star | `ThreadView.onStar`, keyboard `S`, and toast undo `.star` route through `MainScene.starSelectedThread` or `handleUndo` to `MailMutator.star`. | `GmailAPI.modifyThread(id:addLabelIds:["STARRED"], removeLabelIds:[])`. | `thread_label` adds `STARRED`; `ThreadStore.isStarred` updates by GRDB observation. | Toast: `Star failed` or `Undo failed`; optimistic labels roll back in `MailMutator`. | `MailMutatorTests.starAddsSTARREDLabel`; `ThreadStoreStarTests`. |
| Unstar | Same star entry point toggles to `MailMutator.unstar` when `STARRED` exists; toast undo `.unstar` also routes there. | `GmailAPI.modifyThread(id:addLabelIds:[], removeLabelIds:["STARRED"])`. | `thread_label` removes `STARRED`; `ThreadStore.isStarred` updates by GRDB observation. | Toast: `Star failed` or `Undo failed`; optimistic labels roll back in `MailMutator`. | `MailMutatorTests.unstarRemovesSTARREDLabel`; `ThreadStoreStarTests`. |
| Mark read | Menu and keyboard action route through `MainScene.markReadSelectedThread` to `MailMutator.markRead(read:true)`. | `GmailAPI.modifyThread(id:addLabelIds:[], removeLabelIds:["UNREAD"])`. | `thread_label` removes `UNREAD`; messages get the local read flag; `thread.has_unread` becomes `0`. | Toast: `Mark read failed`; local flags and labels roll back in `MailMutator`. | `MailMutatorTests.markReadUpdatesLocalFlags`. |
| Mark unread | Menu and keyboard action route through `MainScene.markUnreadSelectedThread` to `MailMutator.markRead(read:false)`. | `GmailAPI.modifyThread(id:addLabelIds:["UNREAD"], removeLabelIds:[])`. | `thread_label` adds `UNREAD`; message read flags are cleared; `thread.has_unread` becomes `1`. | Toast: `Mark unread failed`; local flags and labels roll back in `MailMutator`. | `MailMutatorTests.markUnreadUpdatesLocalFlags`. |
| Trash | `InboxView.onTrash`, keyboard delete, and menu route through `MainScene.trashThread` to `MailMutator.trash`. | `GmailAPI.modifyThread(id:addLabelIds:["TRASH"], removeLabelIds:["INBOX"])`. | `thread_label` adds `TRASH` and removes `INBOX`; selected reading thread is cleared. | Toast: `Trash failed`; optimistic labels roll back in `MailMutator`. | `MailMutatorTests.trashAddsTRASHRemovesINBOX`. |
| Untrash | Toast undo action `.untrash` routes through `MainScene.handleUndo` to `MailMutator.untrash`. | `GmailAPI.modifyThread(id:addLabelIds:["INBOX"], removeLabelIds:["TRASH"])`. | `thread_label` restores `INBOX` and removes `TRASH`. | Toast: `Undo failed`; optimistic labels roll back in `MailMutator`. | `MailMutatorTests.untrashRemovesTRASHAddsINBOX`. |
| Send | Full compose send button and inline composer call `ComposeViewModel.requestSend`; after approval it resolves `LiveComposeService` and sends through Gmail. | `GmailAPI.sendMessage(raw:threadId:)`; replies pass Gmail `threadId` plus RFC reply headers. | Local sent `message` row is inserted or updated with `sentByMe | read`; the thread gets `SENT`; new thread rows are created for new messages; reply threads update last-message metadata without double-counting duplicate sent IDs. | `ApprovalRow` shows failed send or reauthorize actions; no local sent row is inserted before Gmail success. | `ComposeViewModelTests`; `ComposeServiceTests`; `MIMEBuilderTests`; `GmailAPIClientTests`. |
| Refresh | Keyboard/menu refresh route through `MainScene.refreshCurrentAccount` to `CompositionRoot.refreshAccount` or `refreshAllAccounts`, then `MailSyncSupervisor.refresh`. | Gmail history or bootstrap calls: `listHistory`, `getThread`, `listMessages`, `listLabels`. | Threads, messages, labels, attachments, and sync state are reconciled through `Bootstrap` and `IncrementalSync`. | Toast: `Refresh failed: ...` from `CompositionRoot`. | `MailSyncEngineTests`; `LabelRoundTripTests`; `InboxStoreFilterTests`. |
| Attachment download | Attachment `Summarize` button calls `AttachmentSummaryStore.summarize`, which asks `AttachmentSummaryOrchestrator` to fetch bytes through the Gmail byte provider when no local blob exists. | `GmailAPI.getAttachmentData(messageId:attachmentId:)`. | Bytes are stored in `attachment_blob` via `AttachmentByteStore`; extracted text, chunks, and AI artifacts persist locally when supported. Cached local files expose explicit metadata-only, downloading, cached, preview-available, unsupported-preview, failed, and deleted states; previewable PDF, image, and plain-text-like cached files use Quick Look. | Attachment row shows `Attachment data is not available yet`, unsupported, summary failed, preview unsupported, or cached file deleted states instead of silent success. | `AttachmentSummaryStore` tests; `AttachmentRAGTests`; `GmailAPIClientTests.getAttachmentDataDecodesBase64URLPayload`; `ThreadFeatureTests` attachment UI state tests. |
| Reconnect / re-consent | Settings account connection and compose reauthorize route through OAuth clients and `TokenStore`; missing `gmail.send` during send becomes `ComposeError.needsReconsent`. | OAuth authorization/reauthorization, then Gmail calls retry with updated token. | Account and credential state remain in the existing secure token boundary; compose stays failed until re-consent succeeds. | `ApprovalRow` exposes `Re-authorize`; startup/sync failures show recoverable UI or toast. | `AccountsTabStoreTests`; `ComposeViewModelTests` for reauthorization state. |

No-op UI cleanup from this audit:

- The action sheet now enables only implemented Trust MVP Gmail actions: Draft reply, Archive, Star, Mark read, and Trash. Snooze, CRM log, task, unsubscribe, rule, and share remain visible only as unavailable roadmap items and cannot drive the primary `Do it` CTA.
- Thread-level Snooze and Send to controls are disabled with unavailable tooltips.
- Attachment Preview is limited to supported cached local file types; attachment byte download remains available through Summarize.
- Full compose Save draft and Rewrite controls keep their labels but are disabled with unavailable tooltips.
